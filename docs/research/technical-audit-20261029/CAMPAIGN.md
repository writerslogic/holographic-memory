## Binding execution contract

1. Diagnose actual production flow before editing: inputs, ownership, transformations, allocations, synchronization, persistence, publication, outputs and failures. Support a precise root cause with source, existing evidence or an allowed bounded probe.
2. Reuse existing implementations, types, schemas, fixtures, instrumentation, dependencies and reference oracles; consolidate accidental duplication. Identify the limiting mechanism before replacing a working subsystem.
3. Seek substantial improvements. Compare at least two credible mechanisms for architectural choices, including complementary combinations. Cosmetic tuning, unused abstractions, disabled deliverables or documentation alone do not constitute runtime fixes.
4. Preserve correctness, isolation, security, durability, source fidelity and declared compatibility. For other tradeoffs provide a before/after metric table, workload-weighted justification and investigation of recovering regressions elsewhere. Adapt the mechanism or pair complementary approaches after failure; do not blindly sweep parameters.
5. Until the final session do not run cargo check/test/build/clippy/doc/bench/run/nextest, rustc compilation, native packaging, fuzzing, coverage, large suites, site or dependency builds, or heavyweight CI. There are no quick-build exceptions. Read-only metadata and installed formatters on touched files are allowed.
6. Per implementation session, spend at most 60 seconds on a narrowly selected noncompiling check subset; at most two necessary local diagnostic probes totaling 30 seconds, one worker and a small fixed input. Inspect entry points for hidden builds/downloads. Existing binaries need identifiable source/configuration; stale binaries cannot validate changed code.
7. Author meaningful regression tests and record deferred commands. Never manufacture passing results, infer measured gains from source changes, weaken assertions or treat a merge as validation.
8. No paid APIs/cloud credits, model downloads, remote benchmarks or production-data experiments. Performance experiments are local. Use uv for Python and declared project toolchains.
9. Default to no new inline comments except licensing and genuinely non-obvious contracts. Format only touched files; never log secrets.
10. Default aggregate token ceiling 24,000 per implementation session, including children collectively at most 6,000. Use exposed usage counters if available; never invent counts. Search before reading, bound reads, retain findings once and avoid repeated investigations. Budget exhaustion does not authorize a false completion claim.
11. At most two useful subagents: `gpt-6.1-terra`, high effort, no full-history forks or grandchildren. Provide the complete relevant contract, precise disjoint ownership, bounded budget and compact evidence handoff. Children cannot run expensive operations, commit, push, merge or change CI policy. Coordinator owns integration and validation.
12. At most one temporary branch per session; no new worktrees or stashes. Preserve unrelated work and existing artifacts. Sign and DCO-sign-off commits. Merge the concrete implementation into main, verify remote inclusion, return to main and delete only that session's temporary branch. If repository rules prevent both intermediate merges and final-only expensive validation, identify the exact rule; do not bypass it or spend prohibited compute.

Preserve schema-5 compatibility and explicit upgrades; append-only golden stores; V1 default/V2 opt-in text encoding; effective model fingerprints; canonical f64 dense scoring and Jaccard sparse scores; coherent revision-conditional mutations; typed committed outcomes; bounded resource errors; checked embedding failures before writes.

## Temporary CI and release freeze

All jobs in the workflows listed in [campaign.json](campaign.json) carry an explicit false guard, including scheduled, PR, push, dispatch, reusable, release and deployment paths. Their original job conditions are retained as `campaign-original-if` comments; triggers and commands remain intact. DCO remains active. The cheap Campaign policy checks guards and announces deferral; it does not certify code quality. A skipped job is not a passed quality check. Release/deployment is frozen while provisional work is on main, including manual publication, old tags and historical refs: those refs retain their old workflow definitions and are not protected by these guards. Do not create release tags, dispatch historical workflows, publish manually or deploy until restoration and final validation. This repository change cannot stop privileged external publication or already-running historical workflows.

Original workflow state is `554aec0c21ef84aaafee8feb52fd1553be791d2d`; compare each file to that revision while preserving later intended edits. In the final session remove each `campaign-deferral` marker and its false guard, restore any adjacent `campaign-original-if` to its original `if`, then remove the policy workflow/script and reconcile the ledger. Review every trigger and release path against the baseline and intervening changes. Run the retained full gates on the final implementation, including all-feature/default lint and tests, MSRV, bindings, format, docs, interoperability, package, fuzz and release checks, plus all recorded deferred focused commands. Record exact revision, commands, results, evidence and unresolved limits. Only after successful final validation and review may release/deployment resume; do not weaken branch protection or use skip-CI directives.
