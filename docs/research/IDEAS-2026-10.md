# Ideas tree, October 2026: a step, not a percent

Session artefact of the 2026-10-07 Fable session. Goal: move HMS by a step in the three arenas
(ANN single-thread QPS and index bytes at recall@10 0.90 / 0.95; BEIR nDCG@10; LongMemEval S-dev
end-to-end accuracy) and in product correctness. Ideas come from four methods (axiom relaxation,
isomorphic mapping, counterfactual targets, adversarial counterfactual), are pruned by 10-minute
proxies on dev or held-out data, and only survivors are measured properly.

Rules applied throughout: every number here traces to a file in `benchmarks/results/`; proxies
never read `test.f32`, `neighbors.i32`, BEIR test qrels or the held-out LongMemEval ids; a proxy
that cannot change a decision is not run; no Modal or API spend.

Proxy code: `benchmarks/public/proxies/` (`qgraph_sim.py` is a numpy model of the VGraph search
over a graph read from the HMSGRF02 cache; it reproduces the Rust evaluation counts exactly and
recall within about one point, so it is used for counts and recalls, never for time). Proxy
results: `benchmarks/results/proxies_2026-10.json` (ANN), `proxies_2026-10_lme.json`,
`proxies_2026-10_beir.json`.

## 3. Isomorphic mappings

### 3.1 Graph search as branch-and-bound with the code estimate as a heuristic (ANN)

Objects: vertices = nodes; the ef-pool = the open list; the k-th best fine score = the incumbent;
the 8-bit estimate = the heuristic h(v). Operations: expansion = pop the best open node, push its
children. Invariant: branch-and-bound is exact only when h is admissible (never overestimates the
distance) and it prunes a node when h(v) exceeds the incumbent. Our estimate is not admissible: it
has symmetric error, so pruning on it loses recall, which is why the pool holds ef candidates
rather than pruning on a bound. What the mapping imports: (a) an admissible bound exists cheaply:
|<q, x> - <q, x~>| <= ||q|| ||x - x~|| and ||x - x~|| is known per vertex at build (the residual
norm), so est - scale_err is a true lower bound on the distance; (b) with an admissible bound the
stop rule becomes exact: stop when the best open bound is worse than the k-th incumbent, and no
fixed ef is needed. What is lost: the bound is loose for 8-bit codes (residual norms are small but
not zero), so the exact rule stops later than the heuristic one; whether it stops earlier than a
fixed ef is exactly the `oracle_stop` question. Proxy: `oracle_stop` (the oracle ratio bounds the
gain; the "k-th best unchanged for t steps" rule is the cheapest non-learned stop). Not an
analogy: the structure is identical.

### 3.2 Quantization as rate-distortion and lattice codes (ANN)

Objects: a vertex code = a point of a codebook; bits per vertex = the rate; the estimate error
= the distortion. The current code is a cubic lattice (Z^d scaled per vertex) with one scale.
Theory: at equal rate, (a) a rotation that whitens the coordinates (Gaussianizes them) lowers the
distortion of a scalar quantizer on heavy-tailed data; (b) an asymmetric (min/max) scalar
quantizer uses all 256 levels; (c) entropy-coded or lattice (E8, Leech) codes gain up to 1.53 dB
over cubic at the same rate but cost decode time, which the kernel cannot afford at 20 ns per
estimate; (d) RaBitQ's 1-bit code with a rotation is the rate-1 point of the same curve and its
theory gives the error bound used in (3.1). Imports: rotation (cheap at query time: one d x d
product per query) and LVQ-style min/max. Proxy: `quantizers`. Not an analogy.

### 3.3 Graph build as nearest-neighbour descent (ANN)

Vamana's insert pass searches each vertex from the entry (build_ef) then prunes; NN-descent
instead iterates "a neighbour of a neighbour is likely a neighbour" and converges in a few sweeps
with no search. Imports: (a) NN-descent as the candidate generator for the prune, which removes
the build search that is 85% of glove's build time (spec A3); (b) the alpha-prune is identical
in both, so the graph quality question reduces to the candidate set. Proxy for quality:
`build_params` (alpha and build_ef sweep on 100k rows). Build time is the one metric where losing
is accepted, so this mapping is recorded, not expanded, unless the recall result moves.

### 3.4 Supersession as a bitemporal database with MVCC (agent memory)

Objects: a fact = a row version with valid-time (the event date stated in the text) and
transaction-time (the session date); a question = a query "as of" the question date, or over a
valid-time range. MVCC semantics: the newest version visible at the as-of time wins; older
versions are retained for "what did I say before" questions. The current pipeline stores only
transaction time (M2) and returns every version (M6); the reader resolves. Imports: extract
valid time at ingest (an LLM `dates` stage, specified in spec C lever ii) and index both; answer
temporal questions by valid time and knowledge-update questions by transaction time. Proxy:
`event_dates` (how often valid time differs from transaction time in the evidence). Analogy only
in part: the retrieval is a ranking, not a point lookup, so the MVCC visibility rule becomes a
boost, not a filter.

### 3.5 Memory as a cache hierarchy with admission policies (agent memory)

Objects: the store = a cache; sessions = lines; the question = an access. The hit rate is
recall_all@K; K = the associativity. Admission policy = what gets a key (facts, turns, expanded
turns); replacement = none (the store grows). Imports: (a) the "one line per set" principle:
multi-session questions need one hit per session, so the ranking should admit at most m turns per
session before taking a second turn from any session (set-associative diversification); (b)
prefetching = session-level retrieval followed by turn-level retrieval inside the hit sessions.
Proxy: `diversify` on cached dev embeddings. Analogy (the memory is read, not evicted), but the
diversification rule is concrete.

### 3.6 VSA cleanup as sparse recovery (holographic memory)

Objects: a superposed trace = y = A s where A is the codebook (D x N, +-1 entries) and s the
0/1 membership vector; cleanup = recover s from y. Theory: compressed sensing recovers K-sparse s
with D ~ K log N measurements when A is random; the capacity curves in `holographic_dev.json`
(sign codes fail past K ~ 128 at D = 16,384, random codes past K ~ 512) are exactly the
difference between a structured and a random sensing matrix. Imports: (a) iterative hard
thresholding or OMP as the cleanup (resonator networks are the VSA name for it), which raises the
recoverable K by a constant factor; (b) the result also says why sign codes of embeddings
underperform random codes: they are correlated columns. Proxy: none needed, the capacity file
already shows the K cliff; the dev accuracy of the holographic arms (0.117 to 0.213) is far
below the index (0.821 recall), so this mapping is recorded and not expanded this session.

### 3.7 Hybrid fusion as rank aggregation / social choice (text retrieval)

RRF is Borda-like with a 1/(k0 + rank) kernel. The theory (Kemeny, Condorcet fusion) says rank
fusion ignores score margins, which is what the measured +0.017 of a min-max blend on LongMemEval
sessions showed (`longmemeval_dev_ablation.json`). Import: a calibrated score blend with a
per-query normalization. Proxy: `fusion` on BEIR dev / train qrels. Analogy, but the proxy is
direct.

### 3.8 Learned traversal as a stopping problem (optimal stopping, secretary problem)

Each expansion reveals one more candidate; the reward is recall, the cost is evaluations. The
secretary-problem structure (stop after the best-so-far has not improved for a fraction of the
horizon) is exactly the "k-th best unchanged for t expansions" rule. Analogy, but it names the
cheapest non-learned policy; proxy `oracle_stop`.

## 4. Counterfactual targets

### ANN: 2x QPS at recall 0.95 at equal or fewer bytes

QPS = 1 / (evals x ns_per_eval). Twice the QPS means either half the evaluations at the same
recall (14,850 -> 7,400 on nytimes held-out) or half the nanoseconds per evaluation (20.7 -> 10.4
ns, which is below one cache-line fetch per estimate and therefore requires fewer bytes per
estimate, i.e. the 4-bit code, which already gave x1.2 on nytimes and x1.0 on glove), or a
product of the two. Mechanisms and the proxy that bounds each:

- Early termination (A2, A3): the oracle ratio is the ceiling of what any policy can save.
- Better entry (A1): bounded by the oracle-entry proxy.
- Better estimator (A5 to A7): fewer re-rank candidates and a smaller ef for the same recall.
- Cheaper screen (A8): if most evaluated neighbours never enter the pool, a 4-bit first pass with
  8-bit confirmation halves the bytes per discarded neighbour.
- Better graph (A12): fewer hops at the same recall.
- Error classes that must vanish for 0.95 at ef 128 instead of 384: the true neighbours that the
  pool never sees (`true_neighbours_ever_seen` in `oracle_stop`) versus the ones seen but ranked
  out (`rerank_ceiling`).

### Text retrieval: BEIR nDCG@10 average up by a step (0.68 -> 0.72 on SciFact)

The published numbers that define a step are encoder numbers (SPLADE v3, Qwen3-Embedding-8B);
no index change moves nDCG@10 by 0.04 when exact cosine equals the NumPy reference. What must be
true: the encoder changes (T3), or the hybrid gains a calibrated blend (T1) and proper BM25 (T2),
each worth about 0.01 to 0.02. The honest counterfactual is that a step in this arena is a model
decision (spec B, $150) and this session can only bank the index-side 0.02.

### Agent memory: end-to-end accuracy up by a step

There is no baseline number, so the first step is the reader run itself (spec C). What this
session can move is the retrieval input to it: multi-session recall_all@5 from 0.625 toward the
0.93 of the other types (M1), and dating (M2). Twice the gap closed on multi-session (24 of 84 dev
questions) moves the overall turn recall_all@5 by about 0.04.

### Adversarial counterfactual: a competitor publishes 2x next month

Most likely technique on ann-benchmarks-style CPU numbers: SymphonyQG-style 1-bit edge codes with
FastScan (already in the retired edge index), plus RaBitQ 4-bit extended codes with an
error-bound-based early stop, on AVX-512 with batched queries. On single-thread, one-query, the
realistic 2x comes from (a) the bytes per estimate (4-bit or 1-bit screen) and (b) AVX-512 FastScan
over 32 codes per instruction. We can adopt (a) now (opt-in 4-bit is x1.2 on nytimes); (b) is the
x86 port (spec X) and is not measurable on this M4. What we can surpass: the error-bound stop
(3.1) is cheap to add and SymphonyQG does not use it.
