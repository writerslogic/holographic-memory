Follow-up to merged #204: adds opt-in compact adjacency and experimental production-search profiling, plus completed RF80, layout and kernel research reports. Compaction preserves ordered neighbors and HMSVGR01 persisted bytes while reducing live encoded memory about 23%; it remains default off because the paired timings do not establish a speedup. The original 8-bit/projection/patience features are already in #204.

These are saved-fifth-pass medians across three alternating blocks. Selection uses actual strict recall, without rounding or interpolation. The compared RoarGraph M48/M96 and MLANN RF10/depth14 and RF80/depth13 indexes use the same 32,768 construction queries as HMS. RF80 was declared before official outcomes; both runs completed and their receipts passed the source, CPU, affinity, thread, harness, pool and cache-policy checks. Llama's qualifying RF80 point has recall 0.99007 and QPS 3221.70[2993.35–3226.85]; yi's 0.95 comparator has recall 0.96418 and QPS 1952.60[1951.81–1973.49]. Overall superiority is **not established**. This does not establish superiority over the full VIBE CPU roster. Historical best-of-five standings used a different protocol and remain separate.

On the official llama build, encoded bytes increase from 128,432,748 to 206,536,668 (+60.81%) and build time from 275.927 to 333.071 seconds. Yi increases from 93,802,528 to 150,906,736 bytes (+60.88%), with build time 118.276 to 170.819 seconds. Build times are single observations; process RSS aggregates co-resident indexes, and encoded bytes are not persisted-file sizes. The remaining llama 0.95 throughput gap requires reducing traversal/scoring cost; higher recall alone does not close it.
